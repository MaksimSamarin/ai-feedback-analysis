# Настройка

Скопируйте [`.env.example`](../.env.example) в `.env` рядом с [`docker-compose.yml`](../docker-compose.yml). Compose читает этот файл при запуске команд из корня проекта.

## Первый запуск

| Параметр | Что прописать |
| --- | --- |
| `APP_SECRET` | Длинная случайная строка для шифрования сохранённых API-ключей моделей. Сохраняйте это значение при обновлении и используйте его во всех репликах API и воркеров. |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL, заданного в `POSTGRES_USER`. |
| `DATABASE_URL` | Строка подключения Analyzer к PostgreSQL. Для базы из Compose укажите хост `postgres` и порт `5432`. Пользователь, пароль и имя базы должны соответствовать параметрам `POSTGRES_*`. |

Сгенерируйте независимые значения для `APP_SECRET` и `POSTGRES_PASSWORD` с помощью [команды в инструкции по развёртыванию](../README.ru.md#развёртывание). Пароль базы укажите в обоих параметрах подключения.

```dotenv
APP_SECRET=<random-app-secret>
POSTGRES_USER=review_analyzer
POSTGRES_DB=review_analyzer
POSTGRES_PASSWORD=<postgres-password>
DATABASE_URL=postgresql://review_analyzer:<postgres-password>@postgres:5432/review_analyzer
```

Сгенерированный шестнадцатеричный пароль можно вставить в URL напрямую. Если в существующем пароле есть зарезервированные символы URL, закодируйте их в `DATABASE_URL`. В `POSTGRES_PASSWORD` оставьте исходное значение.

## Подключение модели

Для **OpenAI-совместимого API** укажите базовый адрес и идентификаторы моделей. Адрес можно задать с окончанием `/v1` или без него. Для внешнего API укажите его URL и ключ. Ключ также можно ввести в интерфейсе перед запуском анализа.

Пример для локального сервера модели на хосте Docker Desktop, на порту 8081. Подставьте порт и идентификатор своей модели. Значение `local` подходит, если API принимает запросы без аутентификации.

```dotenv
OPENAI_BASE_URL=http://host.docker.internal:8081/v1
OPENAI_MODELS=my-local-model
OPENAI_API_KEY=local
```

Для **Ollama** укажите адрес и идентификатор установленной модели, затем выберите Ollama в Analyzer.

```dotenv
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_MODELS=llama3.1:latest
```

Адрес должен быть доступен из контейнеров. На Linux можно использовать адрес в сети или имя сервиса в общей сети Docker. Списки моделей заполняют каталог при первом запуске. Дальше управляйте им в разделе **Администрирование → Модели**.

## Доступ и адрес интерфейса

| Параметр | Значение |
| --- | --- |
| `FRONTEND_PORT` | Порт для браузера. В шаблоне указан `8080`. |
| `FRONTEND_BIND_ADDRESS` | Интерфейс, на котором публикуется порт. В шаблоне указан `127.0.0.1`. |
| `CORS_ALLOW_ORIGINS` | Адреса фронтенда через запятую, если он открыт отдельно от API. В стандартном Compose интерфейс и API обслуживаются с одного адреса. |
| `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD` | Задайте до первого запуска для создания локального администратора. Пароль должен содержать минимум восемь символов, включая букву и цифру. |
| `LOCAL_AUTH_ENABLED` | `1` включает вход по паролю. |
| `LOCAL_REGISTRATION_ENABLED` | При включённом входе по паролю пустое значение разрешает регистрацию, если SSO выключен. Для явного выбора задайте `1` или `0`. |
| `SSO_*`, `SESSION_COOKIE_SECURE` | Параметры провайдера, обратного вызова и HTTPS описаны в [настройке OIDC](AUTHENTICATION.md). |

## Обработка и хранение

| Параметр | Значение в шаблоне |
| --- | --- |
| `REQUEST_TIMEOUT_SEC` | `180` секунд на запрос к модели. |
| `GLOBAL_LLM_PARALLELISM` | До `12` одновременных запросов к модели на один воркер анализа. |
| `GROUP_MAX_ROWS` | `100` строк в группе при групповом анализе. |
| `MAX_UPLOAD_SIZE_MB` | `200` для XLSX и CSV. При изменении согласуйте лимит тела запроса в [Nginx](../frontend/nginx.conf). |
| `REPORT_KEEP_LAST`, `REPORT_CLEANUP_INTERVAL_SEC` | Сохранять `20` последних отчётов на пользователя и запускать очистку каждые `600` секунд. Нулевой интервал отключает очистку отчётов. |
| `PAUSED_REPORT_TTL_DAYS` | При `0` приостановленные отчёты остаются на паузе без срока. |
| `SEMANTIC_CACHE_ENABLED` | `1` включает поиск похожих запросов через эмбеддинги. При `0` используется кэш точных совпадений. |

Остальные параметры перечислены в [шаблоне окружения](../.env.example). Проверьте конфигурацию и примените изменения к контейнерам.

```sh
docker compose config --quiet
docker compose up -d --wait
```

Для масштабированного развёртывания применяйте изменения с теми же флагами `--scale` или с вашим Compose override.

## Железо и масштабирование

### Стартовая конфигурация

Запустите по одному экземпляру каждого сервиса Compose. При таком запуске работают **шесть контейнеров**, включая один воркер анализа и один воркер проверки файлов.

```sh
docker compose up -d --build --wait
```

Если модель работает на отдельном сервере, стартовый ориентир для Analyzer — **8 vCPU и 16 ГБ ОЗУ**. При одной реплике каждого сервиса сумма лимитов из [`docker-compose.yml`](../docker-compose.yml) составляет **6,25 CPU и около 11,4 ГиБ ОЗУ**. Если модель работает на той же машине, отдельно заложите ресурсы для неё.

| Сервис | Контейнеров | Лимит CPU на контейнер | Лимит памяти на контейнер |
| --- | ---: | ---: | ---: |
| PostgreSQL | 1 | 3,0 | 4 ГиБ |
| Redis | 1 | 0,5 | 1 ГиБ |
| API | 1 | 0,75 | 1 500 МиБ |
| Воркер анализа | 1 | 1,0 | 2 500 МиБ |
| Воркер проверки файлов | 1 | 0,75 | 2 ГиБ |
| Фронтенд | 1 | 0,25 | 512 МиБ |

Начните с **200 ГБ под данные**. Расширяйте том по мере роста PostgreSQL, загрузок, выгрузок Excel и кэша. При выборе размера учитывайте объём данных и срок хранения отчётов.

### Добавление реплик по мере нагрузки

Посмотрите на очередь анализа и лимиты модели. Если задачи долго ждут и у хоста и провайдера есть запас, добавьте воркер.

```sh
docker compose up -d --wait --scale worker=2
```

При одной реплике остальных сервисов получится **семь контейнеров**. Второй воркер анализа добавляет лимит в 1 CPU и 2 500 МиБ ОЗУ. `GLOBAL_LLM_PARALLELISM` задаёт число одновременных запросов на каждый воркер анализа. В шаблоне указано 12.

Увеличивайте `inspect-worker`, если файлы ждут проверки. После изменения числа реплик `backend` выполните `docker compose restart frontend`, чтобы Nginx обновил адреса API. Для опубликованного порта оставьте один фронтенд.

### Сохранение числа реплик

Чтобы запускать два воркера анализа при каждом развёртывании, создайте `compose.scale.yml` рядом с `docker-compose.yml`. Укажите число реплик в `scale`. Лимиты на контейнер можно задать в том же сервисе через `cpus` и `mem_limit`.

```yaml
services:
  worker:
    scale: 2
```

```sh
docker compose -f docker-compose.yml -f compose.scale.yml up -d --build --wait
```
